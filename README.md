# Formula Alchemy

Браузерная лаборатория: соединяйте физические символы, открывайте формулы и меняйте параметры действующего эксперимента. **React + TypeScript + Vite, Matter.js, Canvas 2D, KaTeX, Web Audio.** Без обязательного сервера приложений, аккаунта игрока и платных API.

**Состояние поставки, 22 сентября 2026:** написан модульный проект с 44 рецептами, 9 тематическими разделами и 8 режимами лаборатории. Проверены вычислительное ядро и интерфейс в ограниченном стенде. **Установить npm-зависимости и получить production-сборку в среде подготовки не удалось. Работа настоящего Matter.js и полный штатный тестовый прогон не подтверждены.** Репозиторий и живой сайт не созданы; конфигурация Actions и инструмент первой публикации включены. Подробные результаты, а не предположение о готовности, — в [docs/QA.md](docs/QA.md).

## Запуск

Нужен Node.js **22.12 или новее** и npm. Распакуйте проект в отдельную папку, затем:

```bash
npm install
npm run dev
```

Откройте адрес, напечатанный Vite, обычно `http://127.0.0.1:5173/`. Открытие `index.html` двойным щелчком не поддерживается: исходный TypeScript должен обрабатывать Vite.

Первый `npm install` создаст `package-lock.json`. Его следует сохранить в Git, а последующие воспроизводимые установки выполнять через `npm ci`. Готового lockfile в архиве нет: в среде подготовки недоступен npm registry. Версии непосредственных зависимостей закреплены в `package.json`; транзитивные зависимости до создания lockfile не зафиксированы.

Для проверки с телефона в своей локальной сети:

```bash
npm run dev -- --host 0.0.0.0
```

Используйте локальный IP компьютера и порт из вывода Vite. Не публикуйте dev-сервер в открытый интернет. На опубликованном Pages-сайте ничего запускать на компьютере не требуется.

## Первые эксперименты

На начальном холсте уже лежат `m` и `g`. Перетащите один символ на другой: получится `F = mg`. Выберите формулу, измените массу или ускорение в панели параметров. Числа пересчитываются, опыт перезапускается с новыми начальными условиями.

Добавьте `h` к `mg`: получится `Eₚ = mgh`. Комбинация `g + h` остаётся промежуточной заготовкой, пока не добавлена масса. У `m + v` два рецепта: по умолчанию кинетическая энергия, альтернативный импульс выбирается в инспекторе. Порядок символов не важен. Дроби, степени и коэффициенты подставляются **по правилам каталога**, а не угадываются произвольным символьным вычислителем.

Откройте книгу: у формулы есть объяснение, ингредиенты, параметры, единицы, границы модели и кнопки подготовки символов / открытия опыта. Открытие примера через книгу отмечается в журнале отдельно от самостоятельного создания. Формулы не заблокированы искусственной прогрессией.

Для чёрной дыры соберите `G + M + c`. Горизонт искажает сетку и поглощает **физические тела**, но не интерфейсные жетоны формул. Масса меняет вычисленный радиус и масштаб художественной визуализации.

## Управление

| Действие | Мышь / клавиатура | Телефон |
|---|---|---|
| Добавить переменную | Перетащить из палитры; коротко нажать — положить на холст | Перетащить или коснуться |
| Собрать рецепт | Бросить символ / заготовку на другой элемент | То же |
| Поменять параметры | Выбрать формулу, ползунок или числовой ввод справа | Выбрать формулу, открыть «Параметры» |
| Переместить физическое тело | Захватить непосредственно на холсте | Перетащить пальцем |
| Добавить свободное тело | «+ Тело» или двойной щелчок по свободному холсту | «+ Тело» |
| Пауза | Пробел или кнопка воспроизведения | Кнопка воспроизведения |
| Скорость | ¼×, ½×, 1×, 2×, 4× | Селектор рядом с паузой |
| Удалить элемент | Delete / Backspace; корзина инспектора; перетащить на область сброса | Корзина инспектора / перетаскивание |
| Очистить опыт | «Сброс» с подтверждением; журнал открытий сохраняется | То же |
| Сохранить | Кнопка сверху или Ctrl/Cmd+S | Значок сохранения |
| Закрыть окно | Escape / крестик / фон | Крестик / фон |

На узком экране палитра находится снизу, раскрывается кнопкой, инспектор — выдвижная панель. У газа можно двигать поршень на схеме; у преломления — источник луча. Цепь имеет работающий выключатель. Музыка и звуковые эффекты выключаются независимо. Звук создаётся синтезатором только после пользовательского действия; музыкальных файлов и внешней загрузки аудио нет.

## Архитектура

```text
src/
  core/
    types.ts          Контракты, снимки состояния, пределы нагрузки
    symbols.ts        Символы, определения, базовые единицы
    catalog.ts        Рецепты и метаданные, без рисования и React
    evaluate.ts       Чистые вычисления, переводы в СИ, особые случаи
    crafting.ts       Мультимножества ингредиентов, заготовки, совместимость
    store.ts          Состояние игры и команды пользователя
    persistence.ts    Версия сохранений, валидация, слоты и JSON
  physics/
    World.ts          Реальный Matter.js: тела, силы, столкновения, захват
    Runtime.ts        Фиксированный шаг, часы, пауза, восстановление
    geometry.ts       Чистая геометрия художественного горизонта
  rendering/
    Renderer.ts       Canvas 2D, сетка, масштаб, тела и следы
    primitives.ts     Общие графические примитивы
    effects.ts        Реестр обработчиков рецептов
    labs/             Механика, теплота, цепи, поля, волны, оптика, кванты, СТО
  audio/AudioEngine.ts
  app/                Сессия, оболочка, pointer-based перетаскивание
  components/         Палитра, холст, инспектор, книга, журнал, сохранения
  styles/app.css      Монохромная адаптивная система оформления
```

React не получает координаты всех тел каждый кадр: физика и Canvas работают вне React-состояния. Интерфейс показаний обновляется отдельно. Шаг механики `1/120 с`, максимум 24 подшага за кадр, входной интервал кадра ограничен `0,05 с`. Во вкладке в фоне симуляция не догоняет пропущенное время.

Логическое поле `1000 × 680`, 32 пикселя на метр в механических сценах. Максимум **32 элемента**, **56 тел**, 52 точки следа на тело, плотность Canvas не выше 1,75 device pixel ratio. Анимации лабораторий имеют собственное время опыта. Изменение параметра сбрасывает начальные условия соответствующего опыта. Схемы используют аналитические законы, а не попытку выразить всё через одно притяжение частиц.

### Как добавить формулу

1. При необходимости добавьте отдельный символ в `core/symbols.ts`, не переиспользуя неоднозначный идентификатор: `c` — свет, `c_heat` — теплоёмкость; `h` — высота, `hP` — постоянная Планка.
2. Добавьте запись `Recipe` в `catalog.ts`: входы, LaTeX, тема, лаборатория, параметры с конечными допустимыми диапазонами, единица результата, объяснение и ограничения модели.
3. Реализуйте вычисление в `evaluate.ts`, включая СИ и вырожденные случаи.
4. Добавьте отдельный эффект в соответствующий `rendering/labs/*` и зарегистрируйте его в `effects.ts`. Для нового механического поведения дополнительно реализуйте его в `World.ts`.
5. Добавьте численные / граничные тесты. Общие тесты проверяют наличие метаданных и обработчика для каждой записи.

Один лишь пункт в книге без вычисления и обработчика не считается реализованной формулой.

## Сохранения и приватность

Автосохранение примерно каждые 10 секунд и при уходе со страницы; восемь именованных локальных слотов; экспорт / импорт JSON. Сохраняются элементы и параметры, позы и скорости тел, возраст опытов, пауза / скорость и открытия. Импорт имеет схему `version: 1`, проверяет допустимые формулы, диапазоны, дискретность параметров и бюджеты; файлы более 500 КБ отклоняются.

Сохранения привязаны к origin браузера, не синхронизируются с другими устройствами и могут пропасть после очистки данных сайта. Для переноса нужен JSON-экспорт. Внутренний кэш контактов решателя Matter не сериализуется: после загрузки возле столкновения возможны небольшие расхождения. Работа файловых сохранений в штатном браузере требует дополнительного прогона — см. QA.

В коде нет аналитики, обязательных сетевых запросов, внешних API-ключей и обязательного бэкенда. После сборки библиотечные ресурсы и шрифты KaTeX должны обслуживаться с того же сайта. Здесь поставлены только ссылки на npm-зависимости, не скопированные системные шрифты.

## Проверки и production-сборка

```bash
npm run check                 # строгий TypeScript, Vitest, затем Vite build
npm run verify:dist           # относительные HTML/CSS-пути и существование ресурсов
npx playwright install chromium
npm run test:e2e              # сборка + desktop/mobile Chromium по настоящему dist
npm run preview:pages         # production dist под /formula-alchemy/
```

Локальная обычная проверка сборки: `npm run build && npm run preview`. Папка публикации — **dist**, не исходная папка проекта.

Штатные тесты: 90 unit/physics случаев и 6 E2E-сценариев в двух профилях (12 запусков), включая все рецепты, параметры, сохранение, относительные пути и мобильную компоновку. Эти штатные прогоны **ещё не выполнены**. Включён также `npm run audit:core`: 80 реальных тестов ядра через адаптер `node:test` и 738 проверок рисования против записывающего Canvas-интерфейса. Он не заменяет Vitest, настоящий браузер или Matter.

## GitHub Pages для TheLitis

### Первая публикация через скрипт

Нужны Git и установленный [GitHub CLI](https://cli.github.com/). Авторизуйтесь самостоятельно; токен не нужно вставлять в исходники:

```bash
gh auth login
npm install
npm run publish:github -- --repo formula-alchemy
```

Скрипт проверит, что аккаунт — `TheLitis`, выполнит сборку, unit/physics и браузерные тесты, **только после успеха** создаст новый **публичный** `TheLitis/formula-alchemy`, отправит исходники и попытается включить Pages в режиме Actions. Он не перезаписывает существующий репозиторий, не использует чужую папку Git и не публикует при провале тестов. Аргумент `--owner` предназначен для сознательного использования с другим собственным аккаунтом.

Включение Pages может требовать дополнительных прав `gh`. При ошибке исходники останутся в новом репозитории; откройте Settings → Pages → Source: GitHub Actions и повторно запустите workflow. Не запускайте инструмент первой публикации для обновления уже созданного репозитория — используйте обычные commit / push.

**Подготовленный ожидаемый адрес после успешного деплоя:** `https://thelitis.github.io/formula-alchemy/`. Он **не является подтверждением существования сайта сейчас**.

### Публикация без скрипта

Создайте пустой публичный репозиторий и отправьте в него содержимое этой папки, включая `.github/workflows/deploy.yml` и полученный `package-lock.json`. В Settings → Pages выберите GitHub Actions. Workflow запускается при push в `main`, выполняет проверки, собирает `dist`, проверяет production-ресурсы и только затем публикует артефакт. Pull request выполняет проверки без публикации. Обновления — обычный `git push`.

`vite.config.ts` использует **`base: './'`**; отдельный history-router не используется. Это позволяет развернуть корневую страницу под именем репозитория без абсолютных `/assets/...`. E2E-сервер специально проверяет сборку под `/formula-alchemy/`, а не только в `/`. HTTPS, сертификат и раздача статических файлов остаются на стороне Pages. Workflow закрепляет официальные Actions по SHA.

## Честные ограничения

Это учебная игровая модель. Чёрная дыра не решает ОТО и не выполняет настоящую трассировку гравитационного линзирования. Цепи — интерактивные заранее заданные топологии, а не произвольный конструктор с решателем Кирхгофа. Оптика — геометрическая и параксиальная; нет полноценного волнового электромагнитного расчёта. Орбита круговая и аналитическая; жидкости не используют гидродинамику. Атом — водородоподобная модель, ядро — иллюстрация дефекта массы без симулятора реакций.

Рецепты общей механики создают свои тела и задают им силы; столкновения и художественная чёрная дыра позволяют взаимодействовать между опытами. Нельзя произвольно «навесить» любую формулу на любое тело. Ускорения и скорости ограничены для стабильности. На графиках и в схемах применяются явно описанные масштабы; число в инспекторе иногда показывает начальную / предельную, а не мгновенную величину — это указано у рецепта.

Нет PWA / установленного offline-кэша, мультиплеера, сервера аккаунтов, контроллера, произвольного редактирования формул или полной клавиатурной замены всех операций drag-and-drop. Диалоги и кнопки имеют клавиатурную навигацию; доступность Canvas для незрячих ограничена текстовым описанием и численными показаниями. Safari / iOS и реальная производительность на телефоне не проверены. Это требует тестирования перед публичным релизом.
