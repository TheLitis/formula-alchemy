#### Как проводился ограниченный UI-прогон

Из среды подготовки нет доступа к npm registry. У Chromium также запрещена навигация к `localhost` и `file://` административной политикой. Эти ограничения не обходились. Поэтому приложение было транспилировано в **временный QA-стенд** и передано Chromium через `page.set_content`.

В стенде использовались реальные React **19.1.1** и KaTeX **0.16.27**, уже доступные в установленном ПО. Это **не те версии, которые закреплены в исходном package.json** (React 19.2.0, KaTeX 0.16.25). Физический интерфейс заменялся **no-op заглушкой исключительно внутри стенда**, а хранилище — памятью стенда. Реальные обработчики аналитических опытов, UI и функции ядра выполнялись. В поставляемом `src` подобных подмен нет: он импортирует настоящий Matter.js.

Временный стенд не включён в поставку и не является приложением для запуска. Его скриншоты показывают фактически отрисованный интерфейс, а не дизайн-макет, но **не подтверждают движение, столкновения и поглощение в Matter**.

Файлы доказательств: [core-audit.log](qa/core-audit.log), [ui-report.json](qa/ui-report.json), [production-build.log](qa/production-build.log), [npm-registry.log](qa/npm-registry.log). Изображения [desktop](qa/desktop-ui.png), [mobile](qa/mobile-ui.png) сняты в этом же стенде. Отдельно показан активный [опыт полного внутреннего отражения](qa/optics-ui.png).

### Ограничения на момент подготовки архива

**`npm run build` был действительно запущен и завершился кодом 1:** TypeScript не нашёл `node` и `vite/client`, поскольку зависимости не установлены. Vite до сборки не дошёл. Это не успешная сборка и не доказательство, что после установки пакетов не останется ошибок типов / интеграции.

Не выполнены: полный строгий TypeScript, настоящий Vitest, 10 тестов Matter, штатные 12 E2E-прогонов production-версии, тесты действительного origin localStorage, загрузка production-шрифтов и JS-чанков, npm audit, деплой GitHub Actions и проверка сайта. Готовых `dist` и `package-lock.json` нет. Приведённые выше 80 тестов — не 90 штатных тестов и не процент покрытия кода.

Не измерялись: реальные FPS / время кадра / энергопотребление, слабые устройства, Safari / iOS / Firefox, экранные дикторы. Пределы нагрузки заложены в коде, но это не подтверждённые показатели производительности.

### Исправления, найденные при проверке

- Самосоединение элемента больше не уничтожает / не дублирует рецепт.
- Импорт проверяет дискретные параметры, включая целые квантовые числа, и дубли открытий.
- Снимок удерживаемого тела сохраняет исходную массу, а не бесконечную массу временно статичного тела.
- Полное внутреннее отражение, линза в фокусе и ниже фокусного расстояния, порог фотоэффекта обрабатываются явно.
- Рабочая область постоянной силы ограничена по обеим горизонтальным границам.
- Мобильные иконки имеют доступные имена; невидимый инспектор исключён из навигации.
- Исправлены расхождения стилей книги / журнала с реальными компонентами.

### Визуальная проверка

Референс — приложенное пользователем видео: светло-серый холст с математическими символами. Оно использовалось как направление, не как материал для точного копирования. Интерфейс создавался непосредственно кодом; нового утверждённого ImageGen-макета нет. Геометрия, сетка, схемы и формулы преднамеренно векторные / программные: они должны зависеть от физических параметров, а не заменяться растровыми сценами.

Проверены: монохромная палитра, математическая типографика и KaTeX, пропорции панелей, свободное место вокруг жетонов, видимые подписи элементов управления, расположение нижней палитры на телефоне, отсутствие горизонтального переполнения, читаемость модальных окон и параметров. Скриншоты desktop и mobile просмотрены. На телефоне сложные схемы масштабируются с сохранением пропорций; отрицательное пространство местами остаётся намеренно. Pixel-perfect сравнение с утверждённым статическим макетом не заявляется.

### Инструкции штатной проверки из исходного архива

```bash
npm install
npm run check
npm run verify:dist
npx playwright install chromium
npm run test:e2e
```

Ожидаемый штатный набор: **90** unit/physics-тестов; **6 сценариев × 2 профиля = 12 E2E**. Playwright запускает `scripts/serve-dist.mjs`, который обслуживает **настоящий собранный dist** под `/formula-alchemy/`. Поэтому тесты могут выявить абсолютные ошибочные пути, а не только проверить Vite dev-server. CI выполняет их до публикации.

Дополнительный проверенный инструмент ядра:

```bash
npm run audit:core
```

Он использует локальный пакет TypeScript. Переменная `TYPESCRIPT_PATH` позволяет указать другую уже установленную копию для аудита в offline-среде. Тесты Matter этот инструмент намеренно не запускает.
